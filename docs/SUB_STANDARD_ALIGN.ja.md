# Sub の標準 Align アルゴリズム

この文書は、Sub モードで歌詞配置アルゴリズムに **Songcut標準**
（内部名 `songcut-standard`）を選び、**歌詞を解析**したときの処理を説明します。

ここでいう Align（アライン）とは、入力された歌詞の各行に対して、
「動画の何秒から何秒まで表示するか」を決めることです。
字幕の上下左右の表示位置を決める `Alignment` とは別の処理です。

## 1. 概要

標準 Align は、カラオケの歌詞表示を自動で作る作業に似ています。
Songcut は完成した曲と歌詞を受け取り、次の順番で字幕の時刻を決めます。

1. **曲から歌声を取り出す**
   - 楽器の音が大きいままだと歌詞を聞き取りにくいため、Demucs で歌声を分離します。
2. **AI に歌声を聞き取らせる**
   - Whisper が、聞こえた言葉とその時刻を小さなまとまりにして返します。
3. **入力歌詞と聞き取り結果を照らし合わせる**
   - 入力歌詞と Whisper の結果は完全には一致しません。
     そこで、文字の抜け・余分・聞き間違いを許しながら、曲全体で最も自然な対応を探します。
4. **各歌詞行の開始・終了時刻を作る**
   - 対応する文字が見つかった行は、その文字の時刻を使います。
   - 見つからなかった行は、前後の見つかった行の間を文字数に応じて分けます。
5. **曲の最初で取り逃した歌い出しを直す**
   - Whisper は、曲の冒頭や短い歌声を取り逃すことがあります。
     MMS という別の仕組みを使い、特に最初の数行の歌い出しを補正します。
6. **字幕の開始をリズムに合わせる**
   - 曲の拍を検出し、近くに十分よい拍がある場合だけ、字幕開始時刻を拍・半拍・4分の1拍へ寄せます。
7. **確認が必要そうな行に印を付ける**
   - 他の行より信頼度が極端に低い行を統計的に見つけ、GUI で確認しやすくします。

つまり、標準 Align は一つの AI の答えをそのまま使うのではなく、
**歌声分離、聞き取り、歌詞との照合、歌い出し補正、リズム補正**
を重ねて字幕時刻を作ります。

処理の全体像は次のとおりです。

```text
動画 + 入力歌詞
  ↓
歌詞の読み取り
  ↓
Demucs でボーカル分離
  ↓
Whisper で時刻付き文字起こし
  ↓
入力歌詞と認識文字を全体整列
  ↓
未一致行を前後から補間
  ↓
MMS で冒頭の歌い出しを補正
  ↓
拍を検出して開始時刻を微調整
  ↓
信頼度の低い行を判定
  ↓
編集可能な字幕行として Sub モードへ配置
```

## 2. 各処理の詳細

### 2.1 入力歌詞の読み取り

入力テキストは行単位で読み取ります。

- 行頭・行末の空白を取り除きます。
- 空行は歌詞行として扱いません。
- 最初の空でない行の直後が空行で、その後にも文章がある場合、
  最初の行をタイトル、空行より後を歌詞として扱います。
- 歌詞行が一つもなければ解析を中止します。

タイトルは歌詞の整列対象には入りません。
解析後、タイトル用字幕として先頭から最大 5 秒間表示されます。

### 2.2 Demucs によるボーカル分離

元の動画音声を OpenVINO 版 HTDemucs に入力し、主に次の二つへ分けます。

- `vocals`: 歌声側
- `no_vocals`: 伴奏側

標準 Align の Whisper と MMS は、どちらも `vocals` を使います。
伴奏を弱めることで、歌詞文字と時刻を見つけやすくするためです。

GUI は解析画面を開く前に、標準 Align に必要な Demucs、Whisper、MMS の
各モデルが利用可能か確認し、必要ならダウンロードします。

### 2.3 Whisper に渡す音声区間の作成

分離したボーカルを 16 kHz、モノラルの音声として読み込みます。
全区間を一度に Whisper へ渡すのではなく、音がある区間に分けます。

1. 音声を 20 ms ごとのフレームに分割します。
2. 各フレームの RMS（音の大きさ）を計算します。
3. RMS が -40 dBFS より大きいフレームを「音がある」と判定します。
4. 250 ms 未満の短い無音は、歌の途中の息継ぎなどと考えて分割しません。
5. 250 ms 以上続く無音で区間を分割します。
6. 100 ms 未満の短い有音区間は除外します。

この方法により、長い無音を Whisper が誤って歌詞として認識する可能性を抑えます。

### 2.4 Whisper による時刻付き文字起こし

各有音区間について、OpenVINO GenAI の Whisper を
`transcribe`、時刻返却ありの設定で実行します。

Whisper が返す時刻は、切り出した有音区間の先頭を 0 秒とした相対時刻です。
Songcut は有音区間の元動画内の開始時刻を加え、動画全体の絶対時刻へ戻します。

たとえば、元動画の 30 秒から始まる区間について Whisper が
「区間内の 1.2 秒から 2.0 秒」と返した場合、記録する時刻は
31.2 秒から 32.0 秒です。

### 2.5 照合用文字列への正規化

入力歌詞と Whisper の文字は、照合するときだけ次の形へそろえます。
表示する字幕本文は変更しません。

- Unicode NFKC 正規化を行います。
- 英字の大文字・小文字を区別しません。
- カタカナをひらがなに変換します。
- 文字と数字だけを残します。
- 空白、句読点、記号を除きます。

例:

```text
入力:  " ホシ・ノ 夜!? "
照合:  "ほしの夜"
表示:  " ホシ・ノ 夜!? " の元の歌詞本文
```

この処理により、「ホシ」と「ほし」、空白や句読点の違いに影響されにくくなります。

### 2.6 Whisper チャンクへの文字時刻の割り当て

Whisper は通常、一文字ごとの時刻ではなく、文章のかたまりごとの時刻を返します。
そこで Songcut は、正規化後の文字がチャンク内で均等な速さで発声されたと仮定して、
チャンクの時間を文字数で等分します。

たとえば、4 文字のチャンクが 10.0 秒から 12.0 秒なら、
一文字あたり 0.5 秒として仮の文字時刻を作ります。

これは最終的な音素時刻ではなく、入力歌詞との対応を探すための近似値です。

### 2.7 入力歌詞と認識文字の全体整列

全歌詞行を連結した文字列と、全 Whisper チャンクを連結した文字列を、
動的計画法で曲全体にわたって整列します。

候補となる操作とコストは次のとおりです。

| 操作 | 意味 | コスト |
| --- | --- | ---: |
| 一致 | 歌詞と認識結果が同じ文字 | 0.00 |
| 削除 | 歌詞の文字を Whisper が認識しなかった | 1.00 |
| 挿入 | Whisper に歌詞にない文字が入った | 1.00 |
| 置換 | Whisper が別の文字として認識した | 1.15 |

表の左上から右下までの合計コストが最小になる経路を選び、
各歌詞文字がどの認識文字に対応したかを逆向きにたどって求めます。
置換を削除や挿入より少し高くすることで、無理に別文字同士を対応させにくくしています。

この整列は行ごとに独立して行わず、曲全体を一度に処理します。
そのため、同じ言葉が複数回出る歌詞でも、前後関係を保った対応を選べます。

### 2.8 Whisper を時刻の根拠にできる行の判定

各歌詞行について、整列で対応した文字と完全一致した文字を数えます。
Whisper の時刻をその行の根拠として採用するには、次の両方が必要です。

- 完全一致文字数が、3 文字以下の行では 1 文字以上、4 文字以上の行では 2 文字以上
- 完全一致文字数が、その行の正規化後文字数の 30% 以上

条件を満たす行では、最初に対応した文字の開始時刻から、
最後に対応した文字の終了時刻までを仮の行範囲にします。
この行の `source` は `whisper-chunk` です。

信頼度は、おおむね次の考え方で 0 から 1 の間に計算します。

```text
信頼度 =
    完全一致率 × 0.75
  + 対応できた文字の割合 × 0.25
  - 多数の Whisper チャンクにまたがった場合の減点
```

4 個目以降の Whisper チャンクにまたがるほど 0.03 ずつ減点し、
減点の上限は 0.20 です。

短い日本語の歌詞に対して Whisper が非常に長い時刻を返す場合もあります。
許容する長さは、正規化後の文字数を `n` とすると次の値です。

```text
最大妥当時間 = max(4.0秒, min(18.0秒, n × 1.2秒))
```

これを超えた行は終了時刻を短くし、超えた割合に応じて信頼度も下げます。

### 2.9 一致しなかった行の補間

Whisper の根拠として採用できなかった行は、`source = interpolated` として補間します。

- 連続する未一致行の前に一致行があれば、その前行の終了時刻を左端にします。
- 後ろに一致行があれば、その後行の開始時刻を右端にします。
- 曲の先頭側に一致行がなければ、最初の Whisper 観測時刻を左端にします。
- 曲の末尾側に一致行がなければ、最後の Whisper 観測時刻を右端にします。
- 左端と右端の間を、各行の正規化後文字数に比例して分けます。
- 補間行の信頼度は 0.05 です。

長い歌詞行ほど長い時間を割り当てる単純な推定であり、
あとで人が確認すべき行であることを低い信頼度で表します。

### 2.10 行範囲の安全な確定

仮の開始・終了時刻を、そのまま使わず次の制約で整えます。

- 開始時刻は 0 秒から動画時間内に収めます。
- 後の行の開始は、前の行より最低 1 ms 後にします。
- Whisper が示した終了時刻へ 250 ms の余裕を加えます。
- 原則として最低 400 ms は表示します。
- 次の行がある場合、終了は次行開始の 20 ms 前までにします。
- それでも長さが 0 以下になる場合、最低 1 ms の正の長さを確保します。
- 最終的な時刻は 1 ms 単位に丸めます。

これにより、歌詞行の順序が逆転したり、字幕時間が負になったりすることを防ぎます。

### 2.11 MMS による冒頭の歌い出し補正

Whisper の全体整列後、標準 Align は MMS Q4 強制アラインメントモデルを使います。
MMS は入力歌詞を既知の正解文として、音声のどこでその文字列が発音されたかを探します。

前処理では、言語コードに従って Uroman で歌詞をローマ字化し、
小文字の `a-z`、アポストロフィ、空白だけへ正規化します。
MMS の語彙に存在する文字をトークン ID に変換し、ボーカル音声から得た
各時刻フレームの文字確率と照合します。

照合には CTC Viterbi 経路探索を使います。
歌詞行の間には「歌詞に対応しない音声」を受け持つ star 状態を置けるため、
間奏などを飛び越えながら歌詞順を守った経路を選べます。

MMS の結果は全行を無条件に上書きしません。

1. Whisper 由来で信頼度 0.45 以上の最初の行を探します。
2. その行より前の不確かな行は、MMS の開始・終了時刻で置き換えます。
3. 最初の信頼できる Whisper 行自身は、MMS が 250 ms 以上早い歌い出しを示した場合だけ、
   開始時刻を MMS 側へ早めます。終了時刻は Whisper の値を保ちます。
4. それより後の行は Whisper の結果を保ちます。

補正元は、MMS で置き換えた行では `mms-ctc`、
Whisper 行の開始だけ早めた場合は `whisper-chunk+mms-onset` になります。

この限定的な使い方により、MMS は得意な「冒頭の取り逃し」を補い、
すでに安定している Whisper の後半結果を壊さないようにしています。

### 2.12 拍検出とリズムグリッド

MMS 補正後、元動画の音声から librosa の動的計画法ベースのビートトラッカーで
BPM と拍時刻を検出します。拍が 2 個未満なら安定した拍列がないと判断し、
リズム補正を行わず、それまでの字幕時刻を使います。

拍が検出できた場合、隣り合う拍の間に次の候補点を作ります。

| グリッド | 拍からの位置 | 引き寄せ半径 | 選択時の減点 |
| --- | --- | ---: | ---: |
| 拍 | 拍そのもの | 120 ms | 0.00 |
| 半拍 | 区間の 1/2 | 80 ms | 0.15 |
| 4分の1拍 | 区間の 1/4、3/4 | 50 ms | 0.35 |

字幕開始時刻に近い候補ごとに、次のスコアを計算します。

```text
スコア = 元の開始時刻からの距離 ÷ 引き寄せ半径 + グリッドの減点
```

元の時刻を残す場合のスコアは 1.0 です。
候補のスコアが 1.0 より小さいときだけ移動し、同点なら
`拍 → 半拍 → 4分の1拍` の順で強いグリッドを優先します。

候補はさらに、次の安全条件をすべて満たす必要があります。

- 一つ前の調整済み開始時刻より 1 ms 以上後
- 次の行の元の開始時刻より 1 ms 以上前
- 自分の終了時刻より 1 ms 以上前

開始時刻の移動で前の字幕と次の字幕が重なる場合は、
前の字幕の終了を次の開始の 20 ms 前へ短縮します。
正の表示時間を作れなくなる移動は取り消します。

拍検出やリズム補正だけが失敗した場合、歌詞解析全体は失敗にせず、
`beat_warning` を付けて Whisper と MMS までの結果を返します。

### 2.13 信頼度の外れ値判定

最終行の信頼度について、第1四分位数 `Q1` と第3四分位数 `Q3` を求めます。
次の境界より低い行を、低信頼度の外れ値として扱います。

```text
下限 = max(0, Q1 - 1.5 × (Q3 - Q1))
```

これは箱ひげ図でも使われる Tukey の方法です。
単に固定値より低い行をすべて警告するのではなく、
その曲の他の行と比べて特に信頼度が低い行を見つけます。

該当行には `low_confidence_outlier = true` が付き、Sub モード上で確認対象になります。

### 2.14 Sub モードへの配置結果

解析結果の歌詞行は、空いている Lyrics レーンへ次の情報とともに配置されます。

- 元の歌詞本文
- 開始・終了時刻
- 信頼度
- 時刻の根拠を示す `source`
- 一致文字数、完全一致文字数、全文字数
- 低信頼度外れ値かどうか

結果にはこのほか、使用デバイス、Whisper 認識全文、BPM、拍時刻、
リズムグリッド、Demucs モデル名、MMS 診断情報などが含まれます。
自動処理の結果は確定値ではなく、Sub モードのタイムライン上で編集できる初期案です。
